# 多 Agent 改造计划

## 目标

- 将子代理列表和只读子对话移到右侧栏。主区继续显示父对话，顶部保留计划清单。
- 父代理通过 `spawn_agent` 和 `send_message` 向子代理下达指令。子代理通过邮箱向父代理报告进度和结果。
- 对话标明消息来源。父代理按需读取邮件，父对话仅显示读信操作和主题。

## 现有结构

父对话下直接挂子会话，每个子会话各自保存多轮 Run。新的分派追加子会话，重复执行同一个 `spawn_agent` 调用复用原会话。每个父对话只有一份计划，`update_plan` 按 `revision` 整体更新条目。计划条目和子会话之间没有关联。第一版沿用这个数据结构和现有并发限制，子代理列表按父对话显示。

目前 [AgentTeamPanel](../src/renderer/src/agent/components/conversation/AgentTeamPanel.vue) 持有树订阅，点击子会话会切换主区。运行时把上下行消息和完成回执都放进同一收件箱，再由 [deliverMessages](../src/agent-core/runtime/session/session-model-context.ts) 注入接收方的时间线。[消息投影](../src/agent-core/contracts/agent-responses/presenter.ts) 将时间线里的消息统一标成 `assistant`，导致上行消息显示成父代理的回复。

## 1. 子代理右侧栏

- 将右侧栏工具页的「浏览器」换成「子代理」。列表展示当前父对话的子会话，复用二级侧栏的运行中、停止中和等待审批提示。保留停止单个子代理和停止整树的入口。
- 点击子会话，在右栏内打开对话，提供返回列表的入口。复用 `AIResponseConversation` 和 `AgentResponseOutput` 的消息、工具、推理和流式滚动。适配窄栏，第一版省略输入框和追加指令表单。
- 右栏按父会话 ID 管理选中的子会话。消息、错误、滚动状态、附件预览和下载都使用子会话 ID。切换子会话时，主区的选中会话、输入框和草稿继续归属父对话。旧版本曾记住子会话为主区选中的会话，恢复时定位到其父对话。
- 将 `agent:watch-tree` / `agent:tree-events` 订阅移到父对话层。关闭右栏时继续接收事件，切换父对话时清理旧订阅。列表从树成员和按会话存储的运行状态读取数据。
- 树快照提供每个成员最近一次 Run。打开子对话时使用 `sessions.context` 补齐全部历史，包括正在运行的子会话。按 Run ID 合并历史与现有流式状态，同一 Run 保留序号更新的快照或增量，丢弃已切走会话的过期视图请求。测试持续流式更新时的历史加载。

主要入口为 [右栏标签页](../src/renderer/src/agent/components/right-sidebar/AgentSidebarTabs.vue)、[消息区](../src/renderer/src/agent/components/conversation/MessagesArea.vue) 和 [会话状态](../src/renderer/src/agent/composables/useAgent.ts)。

## 2. 消息来源和下行指令

- 在持久化消息、历史响应和流式消息项中加入可选的结构化来源。区分用户输入、代理生成和运行时生成。代理来源记录发送会话及来源 Run，UI 据此显示「父代理」「子代理」或具体模型名。模型名从来源 Run 的模型快照读取。
- 模型的 `role` 继续表达消息在上下文中的角色。`spawn_agent` 的初始 prompt 保留 `user` 角色，来源为父代理。真正的模型回复和运行时合成提示在各自生成点写入来源。
- 父代理的 `send_message` 只接受直属子会话。先持久化指令，再调度执行。子代理空闲时，以排队的实际指令作为新 Run 的 `user` 输入。子代理运行中时，在下一次模型调用前按顺序将指令追加到时间线，保留 `user` 角色和父代理来源，前端在对应位置渲染。等待审批时保留队列，原 Run 恢复后再投递。
- 缩小 `deliverMessages()` 的职责，使其只投递子代理指令。指令以来源 Run 和工具调用 ID 去重，持久化到会话后确认投递。重启时通过消息 ID 检查是否已写入。Run 结束检查、停止和恢复沿用现有调度边界，只有待投递指令参与继续执行的判定。
- 如果保留现有桌面 `agents.message` 入口，用同一指令队列，并记录真实来源为用户。第一版右栏省略此入口的输入界面。

## 3. `agent-team` 和邮箱

将 `subagent.ts` 改为 `agent-team.ts`，同步更新工具注册、权限名单、运行时提示词和测试。工具暴露和执行时都检查会话关系。运行时确定发件人和收件人。

| 工具 | 调用方 | 行为 |
| --- | --- | --- |
| `spawn_agent`、`send_message` | 父代理 | 创建直属子代理或追加指令 |
| `send_mail` | 子代理 | 向直属父代理发送主题和正文 |
| `wait_for_mail` | 父代理 | 等待符合条件的未读邮件，支持按发件子代理筛选、超时和取消，返回邮件元数据 |
| `list_mail` | 父代理 | 按发件人、已读状态筛选，分页返回邮件元数据 |
| `read_mail` | 父代理 | 按 ID 读取正文并标记已读，允许重复读取 |
| `wait_agents` | 父代理 | 等待子代理运行状态变化。结果正文统一从邮箱读取 |

邮箱按收件会话查询。邮件保存 ID、发件人、收件人、主题、正文、发送时间、来源 Run、类型和已读状态。主动发信按来源 Run 和工具调用 ID 去重，自动回执按子 Run ID 去重。子 Run 完成、失败或取消等终态仍产生自动回执，由运行时写入邮箱。

邮件入库后通知正在等待的 `wait_for_mail`。等待应先查已有邮件，并处理查询和注册等待之间的竞态。超时或取消时释放等待资源。空闲父代理下次执行时可查阅邮箱，待审批父代理继续等待原审批。父代理提示词应引导模型在需要汇总结果时调用 `wait_for_mail` 或 `wait_agents`，再按需读信。

`read_mail` 的完整正文作为工具结果保存在内部模型上下文。桌面流式事件、树快照、历史响应和可展开工具详情统一投影为读信操作与邮件元数据。邮件正文留在邮箱和内部工具结果中。同步检查 `wait_agents`、`list_agents` 的结果投影，避免通过状态工具把子代理结果正文带回父对话工具详情。

## 4. 数据迁移和验收

### 兼容旧数据

- 为邮箱增加独立持久化表。升级时按发件人与收件人的父子关系，将旧 `agent_messages` 的上行消息和完成回执迁入邮箱，保留消息 ID、来源 Run 和去重关系。已消费的邮件按已读处理。旧表缺少发送时间时保留未知时间，使用原有顺序排序。
- 旧的下行记录保留投递状态。已写入子会话的指令保持原消息 ID，避免重启后重复投递。老消息只在来源可确认时补标，其余显示为未知。已经进入父对话历史的上行消息，如能用原消息 ID 与迁移邮件匹配，前端按邮件元数据展示，保留原始历史供模型上下文读取。
- 保留已有会话、Run、计划和待审批状态。升级和恢复过程只迁移数据，后续模型执行由显式交互或新的下行指令触发。

### 验收场景

- 同一父对话两次分派，列表保留两批子会话。更新计划时子会话列表继续可用。
- 两个子代理并行流式执行。主区继续显示父对话，右栏能切换子会话、查看完整历史和实时状态。关闭并重开右栏、切换同一项目下的父对话，以及重启后恢复旧会话选择时，视图归属正确。
- 空闲、运行中、等待审批三种状态下的下行指令按序投递，子对话显示实际指令和来源。覆盖持久化后、确认投递前重启的场景。
- 验证邮件先到、后到、并发到达、超时、取消和重启后读取。验证邮件和完成回执的去重，以及对子会话和邮箱访问范围的校验。
- 父代理能通过工具读到邮件正文并汇总。父对话的流式消息、历史回放、工具展开区均仅显示读信操作和元数据。后台来信期间，空闲或待审批的父代理保持原运行状态。
- 执行 `pnpm test:multi-agent`、`pnpm test:agent-ui` 和 `pnpm build`。在 Electron 中验证右栏交互、流式显示与邮件正文的展示范围。
