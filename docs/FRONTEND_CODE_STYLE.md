# 前端代码整理规范

本规范适用于 `src/`，包括 `src/agent/`。`agent/` 和 `src-tauri/` 不属于本规范范围。

## 基本原则

- 整理任务默认不改变业务行为、UI 表现、请求时机或组件对外接口。
- 格式问题交给 Prettier；代码问题交给 ESLint；类型问题交给 `vue-tsc`。
- 不为了追求“看起来更抽象”而拆分简单函数或组件。
- 不在格式整理任务中顺便重命名公共 props、emit、路由、store 字段或服务接口。
- 每个整理任务限制修改范围，跨模块修改必须说明原因。

## 格式

- 使用 2 个空格缩进、单引号、语句末尾保留分号。
- 单行建议不超过 100 个字符，但模板可因可读性适当例外。
- import 放在文件顶部，并按外部依赖、项目绝对路径、相对路径分组。
- 不手工调整 Prettier 已经能处理的空格、换行和逗号。

## TypeScript

- 优先使用明确的类型、联合类型和泛型，避免新增 `any`。
- 不使用 `as any` 绕过类型检查；确实无法建模时使用 `unknown`，并在边界处收窄。
- 类型只在一个功能域内使用时，放在使用它的文件附近；跨文件共享类型放入对应的 `src/types/` 或功能目录。
- 常量使用 `const`；变量名表达业务含义，不使用无意义的 `data`、`item2`、`temp` 等名称。
- 只删除确定无用的代码，不删除看似无用但可能由模板、事件或动态调用使用的成员。

## Vue 组件

推荐的 `<script setup>` 顺序：

1. import
2. props、emits 和暴露接口
3. 常量和类型相关声明
4. 响应式状态
5. computed
6. watch、生命周期和副作用
7. 事件处理函数和其他业务函数

- props 和 emits 优先使用 TypeScript 类型声明。
- 复杂模板表达式移到 computed 或命名函数中。
- watcher 必须保留清晰的触发源和副作用；不为了减少代码行数合并无关 watcher。
- 组件变大时，先按职责识别逻辑边界，再决定是否拆分；拆分必须保持原有 props/emits 行为。
- 模板属性顺序统一交给 ESLint 自动检查，不手工制造与逻辑无关的 diff。

## 命名和文件

- Vue 组件使用 PascalCase 文件名。
- composable 使用 `useXxx`，工具函数使用描述行为的动词开头命名。
- boolean 使用 `is`、`has`、`can`、`should` 等前缀。
- 事件处理函数使用 `handleXxx`，异步加载函数使用 `loadXxx` 或 `fetchXxx`。
- 不在一次任务中进行大范围文件重命名；重命名单独处理。

## 验证要求

每个整理批次至少执行：

```text
pnpm format:check
pnpm lint
pnpm build
```

如果某项在整理前已经失败，任务需要区分“本批次新增问题”和“已有问题”，不能用自动修复掩盖失败。
